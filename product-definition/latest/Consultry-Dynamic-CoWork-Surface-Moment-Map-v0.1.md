## 1. Purpose and boundary

This map assigns the dynamic Co-Work block families to the moments in which they may materially improve consulting work. It answers:

> What does the user need to understand, contribute, compare or decide here—and which representation reduces that work best?

It does **not** define a fixed screen sequence, universal wizard, final navigation, complete workflow or one compulsory visualization per step. A short sentence or normal Artifact view remains preferable whenever it communicates the work more clearly.

The mapping covers:

- horizontal moments that recur across the Consultry Product;
- the existing-client ERP continuity corridor;
- the net-new KRITIS Tender contrast;
- active consulting work, Artifact Alignment and governed-reuse continuation;
- Boutique and Growing Specialist Consultancy projections.

## 2. Representation-selection grammar

All representations in this map are rendered inside the associated parent flow. Source/Evidence review, Outcome Tests, confirmations, Trust/Assurance and Effect/Handoff review may expand inline, in a contextual sidepanel/drawer or as a focused sub-canvas, but they do not become standalone modules or global-navigation destinations. Every expanded child keeps the parent Case/Task/Artifact/Plan, Goal, version, owner and return path visible or immediately recoverable.

The Agent may propose a Surface composition, but the semantic shape of the user's current need determines the suitable block.

| Current need | Preferred block family | Use only if | Do not substitute with |
|---|---|---|---|
| understand affected objects, actors, sources or dependencies | **Context / Relationship Visual** | the relationship changes understanding or action | decorative network graph |
| understand sequence, change, deadline, branch or handoff | **Process / Decision Diagram or Timeline** | ordering or dependency matters | generic stepper or fake state machine |
| compare claims, versions, criteria, options or concerns | **Comparison / Evidence Matrix** | the comparison dimensions are source-visible | undifferentiated AI summary |
| understand a numerical trend, variance, distribution or composition | **Quantitative Chart** | exact metrics, units, period and sources exist | invented score, decorative chart or qualitative data disguised as numbers |
| supply missing intent, knowledge, judgment or prioritization | **Adaptive Question Set** | the answer materially changes Goal, Plan, Work Result or next Agent step | long interrogation or closed form for an open problem |
| reduce blank-page effort or show the expected answer/output shape | **Few-shot Suggestions** | origin and example status can be made clear | preselected answer, hidden default or fabricated firm precedent |
| inspect or change the actual consulting output | **Artifact / Plan Surface** | an exact Work Result or version exists | chat response about the Artifact |
| understand what is supportable or claimable | **Outcome-Test / Claim Surface** | the relevant Task, Result, Plan or Client-Progress test is named | one opaque confidence score |

Every dynamic block carries a purpose statement in plain language: `Warum zeigt Consultry mir das jetzt?`

## 3. Horizontal Co-Work moments

These moments may appear in any Journey Family. They are moment archetypes, not mandatory phases.

| Moment | User need | Dynamic Surface candidate | Human-Agent interaction | State consequence |
|---|---|---|---|---|
| **Attention / Why now** | decide whether an item deserves attention | compact change/timeline marker or a tiny affected-context relationship view; often plain text is enough | open, defer, route, dismiss or continue | attention disposition only; no business decision inferred |
| **Context orientation** | understand the Client/Project/Case/Artifact and material relationships | Context / Relationship Visual with a short Agent explanation | inspect nodes, open source/object, correct an assumed relation | corrected or confirmed Working Context |
| **Goal framing** | make the intended result and boundaries explicit | Adaptive Question Set plus editable Few-shot goal/output examples | choose, combine, rewrite or enter an own answer | Goal/Work Brief draft; not Approval |
| **Plan shaping** | decide how the work should proceed | Process/Plan Diagram, dependencies and a small question set around constraints | edit steps, add missing work, stop or replan | accepted or revised working Plan |
| **Analysis and development** | compare evidence, alternatives or interpretations | Comparison/Evidence Matrix; chart only for real quantitative evidence | challenge, annotate, add evidence, request expert/context | analysis state and open obligations |
| **Artifact/Plan production** | create or improve the actual Work Result | Artifact/Plan Surface with contextual examples and source-linked suggestions | apply, edit, reject or ask for a variant | exact Draft/Plan version changes |
| **Outcome testing** | distinguish supported, unsupported and not-yet-observable results | Outcome-Test / Claim Surface, optionally with a source-backed chart or comparison | inspect test, add evidence, accept failure, rework or bound the claim | Evidence State and Claim Ceiling update |
| **Responsible disposition** | select the next responsible path | bounded Question/Option Set with own-answer path and explicit consequence preview | choose/edit rationale, hold, route or decline | human disposition; still no Effect until separately initiated |
| **Effect / Handoff** | understand what will change and who receives responsibility | Effect/Handoff Diagram or Timeline with exact subject/version/destination | confirm, request context, change destination or cancel | simulated Effect/Handoff outcome and next responsibility |
| **Observe / Learn / Reopen** | understand later outcome or changed basis | Timeline, before/after comparison or relationship-impact view | reaffirm, reopen, correct, withdraw or propose learning | Outcome/Learning/Revalidation state |

## 4. ERP existing-client continuity corridor

The ERP corridor should feel like one connected consulting workstream, not a tour through feature screens.

| ERP moment | Primary dynamic composition | Example Agent explanation or question | Few-shot use | Why it matters in the Mock |
|---|---|---|---|---|
| **Additional need emerges in active Client Work** | Client–Project–Observation context visual showing active ERP work, originating conversation and potentially affected scope | `Ich ordne die Beobachtung dem aktiven Projekt zu; offen ist, ob sie bestehende Delivery oder einen neuen Bedarf betrifft.` | example formulations for a concise Observation; never a prewritten Opportunity | proves low-friction Capture plus context continuity |
| **Responsible routing / qualification** | bounded Question Set over responsible routes, always including `Eigene Einordnung` and `mehr Kontext nötig` | `Wie soll dieser Bedarf zunächst behandelt werden?` with Delivery, Follow-on pursuit, merge, hold/no action and own path as candidates | short examples explaining when a route could fit; not a recommendation vote | proves that AI structures the choice without forcing Sales semantics |
| **Engagement framing** | Context/Stakeholder relationship view plus editable Need/Outcome/Constraint frame | `Welche Veränderung soll der Kunde tatsächlich erreichen, und was gehört ausdrücklich nicht dazu?` | examples of outcome statements, exclusions and clarification questions from permitted source classes | makes the output boost tangible before proposal writing |
| **Commitment preparation and challenge** | solution/dependency diagram plus Evidence/Feasibility matrix across claims, expertise, capacity, delivery and open risk | `Diese Zusage hängt aktuell von drei noch ungesicherten Annahmen ab.` | examples of supportable claim wording, delivery options and targeted expert questions | demonstrates source-bound proposal/concept co-work |
| **Readiness and Project handoff** | Commitment-to-Project dependency/handoff diagram with unresolved obligations | `Das Commitment ist wirksam; für die Aktivierung fehlen noch X und Y.` | examples of residual-risk wording or context requests | prevents `won = activated Project` collapse |
| **Active consulting work on Artifact/Plan** | Goal/Plan view connected to the exact Artifact/Plan Surface and current Project sources | `Wir arbeiten jetzt am Work Result, nicht nur an einer Antwort.` | example Artifact structures, review questions and bounded alternatives | proves day-to-day Co-Work and tangible deliverable improvement |
| **Source change or Challenge becomes relevant** | version timeline plus claim/source comparison matrix | `v3 verändert die Grundlage dieses Claims; die Auswirkung ist noch nicht entschieden.` | alternative explanations and response candidates with visible AI origin | explains the challenge without making AI the judge |
| **Human assessment and response** | two separate Question Sets for substantiation and current materiality, followed by consequence preview | `Ist der Widerspruch belegt?` and separately `Ist er für den aktuellen Zweck wesentlich?`—each with own answer/context path where applicable | response options such as targeted evidence, revision, conditional use, hold or no action | preserves the ratified semantic separation and human responsibility |
| **Artifact revision and Outcome Testing** | exact-version Artifact diff, Alignment/Evidence matrix and Outcome-Test/Claim surface | `Der neue Draft behebt den Claim, aber Client Acceptance bleibt nicht beobachtet.` | source-bound wording and structure examples; no invented PASS | connects output boost to verifiable quality and Claim Ceiling |
| **Controlled continuation / Effect** | exact version–purpose–destination–actor diagram and effect preview | `Freigegeben wird nur die benannte Verwendung dieser Version; der Client entscheidet weiterhin selbst.` | example handoff note or steering summary | makes responsibility and real consequence legible |

## 5. KRITIS Tender contrast corridor

The Tender reuses the same Co-Work grammar but must feel meaningfully different from an existing-client observation.

| Tender moment | Primary dynamic composition | Adaptive interaction | Few-shot / visual candidate | Required distinction |
|---|---|---|---|---|
| **Source intake and change orientation** | authoritative-document timeline with amendment/version lineage | ask which Lot/purpose is in scope only when ambiguous; own answer/context request available | concise generated document-change summary with direct source links | no invented Client history or CRM-first intake |
| **Eligibility and criteria understanding** | criteria/evidence matrix and deadline/dependency timeline | user confirms applicability, missing sources and clarification needs | examples of what qualifies as evidence for each criterion, marked generic/firm/source-derived | structured understanding is not a Bid decision |
| **Bid / No-Bid / Hold** | bounded decision frame combining hard blockers, evidence gaps, capability/capacity and risk | selectable rationale candidates plus `Eigene Begründung` and `nicht ausreichend beurteilbar` | examples of responsible No-Bid, Hold or Bid-with-conditions rationales | negative disposition remains valid progress |
| **Tender response work** | criterion-linked Artifact/Plan Surface with coverage matrix and dynamic QA questions | questions focus only on unresolved criterion, claim or delivery assumption | few-shot answer structures and approved proof patterns, never unsourced firm claims | proves artifact output acceleration and criteria alignment |
| **Quantitative decision support candidate** | simple bar/composition chart for published criterion weight or actual capacity/timeline evidence, with table fallback | user may inspect definition, unit, source and scenario assumptions | no synthetic fit score; use matrix if source data is not truly numeric | tests useful charting without dashboard theatre |
| **Commitment readiness and Delivery handoff** | Award/Commitment-to-Project dependency and handoff view | accept, reject or request exact missing context | examples of residual obligation and delivery-start notes | Award does not silently activate Delivery |

## 6. Knowledge, Artifact Alignment and reuse continuation

| Moment | Primary dynamic composition | Adaptive interaction | Result boundary |
|---|---|---|---|
| **Applicable bases for the current Artifact** | relationship view connecting exact Artifact/version and purpose to current Project sources, firm Knowledge/Method/Proof, Brand/CD and Governance/Release bases | user corrects applicability or requests missing basis | retrieval relevance does not become Alignment truth |
| **Alignment-aware creation or revision** | Artifact Surface plus three-perspective concern matrix; source-linked suggestions inline | apply/edit/reject suggested content, structure or presentation | AI contribution remains separate from exact human-selected version |
| **Exact intended-use consideration** | comparison of open/closed concerns, Outcome Tests and Claim Ceiling | user determines further work, bounded use, hold or own responsible path | no universal aggregate alignment score |
| **Effect failure or changed destination** | effect timeline and recovery card | retry, select permitted alternate, hold or cancel | prepared Artifact remains; false success is impossible |
| **Cross-project overlap detected** | Project–Problem–Solution relationship visual with shared aspects, material differences, Sources and uncertainty | `Welche Beziehung liegt vor?`—same problem, complementary solution, conflict, intentional difference, false positive or own answer | system retrieves the pattern; Consultants do not manually maintain a pattern library |
| **Coordinate current work** | comparison matrix of overlapping Work Items/solution paths and affected people | choose discuss, coordinate, keep separate, use existing asset or route | current Project work is not blocked by productization |
| **Optional ReuseCandidate** | source-lineage and rights/de-identification dependency diagram | reject, merge, propose candidate or request Practice/Knowledge input | no raw Client Artifact becomes a ReusableAsset |

## 7. Progressive-disclosure placement

The same dynamic block can appear at different depths without duplicating the underlying object.

| Level | Dynamic treatment |
|---|---|
| **L0 Attention** | at most a compact signal of change/impact; no full graph, chart or questionnaire |
| **L1 Work Brief** | one short visual takeaway, key relationship/change and why it matters now |
| **L2 Co-Work Detail** | interactive diagram/matrix/chart, adaptive Question Set, Few-shot Suggestions and editable Work Result |
| **L3 Assurance** | exact sources, versions, metric definitions, uncertainty, example origin, Skill/run provenance, policy and audit |

Important uncertainty, blocked responsibility or missing authoritative source may be promoted to L0/L1. Detailed provenance stays available at L3; it must not be copied into every default card.

## 8. Boutique and Growing projections

The dynamic composition changes responsibility presentation, not Product semantics.

### Boutique

- one person may answer, work, assess and complete the Consultancy result within actual Authority;
- the Surface shows responsibility-context changes without inventing a second reviewer;
- questions are batched around the actual work so AI does not create coordination overhead;
- Few-shot Suggestions and visual context should reduce senior blank-page and reconstruction work.

### Growing Specialist Consultancy

- the same Question Set may request bounded input from a Contributor or Expert;
- relationship/handoff visuals make accepted contribution, current ownership and next responsibility explicit;
- contributions update the shared Case/Artifact context but do not silently transfer accountability;
- the accountable person receives the integrated result rather than several disconnected Agent or human answers.

## 9. Minimum dynamic-Surface coverage for the first Click Dummy

The Mock does not need every possible combination. The minimum useful coverage is:

| Fixture ID | Required dynamic proof | Suggested anchor |
|---|---|---|
| **DS-1** | Context/Relationship Visual with correction/open-source action | ERP additional need or Artifact-basis context |
| **DS-2** | Adaptive Question Set with single-/multi-choice, own answer and `more context` recovery | ERP routing/qualification or KRITIS Bid decision |
| **DS-3** | Editable Few-shot Suggestions with visible origin and no default selection | Engagement frame, Tender response or Artifact revision |
| **DS-4** | Comparison/Evidence Matrix tied to exact sources/versions | KRITIS criteria or ERP v2/v3/v7 comparison |
| **DS-5** | Process/Decision/Handoff Diagram or Timeline with current position | Readiness/Activation, source change or controlled Effect |
| **DS-6** | Outcome-Test / Claim Surface separating supported, provisional and untestable outcomes | ERP Artifact/Plan or Tender readiness result |
| **DS-7** | optional quantitative Chart with definitions, source and table alternative | published Tender weighting or real capacity/timeline fixture only |

`DS-1–DS-6` are mandatory prototype coverage. `DS-7` is conditional on a meaningful numeric fixture; no chart is better than a fabricated one.

## 10. Validation questions

Moderated testing should observe rather than explain:

- Does the participant infer why this representation appears now?
- Can they explain its main takeaway and then find the supporting source or uncertainty?
- Do they correct an incorrect relationship, option or example instead of trusting it automatically?
- Does the adaptive Question Set reduce clarification effort without narrowing their real answer?
- Are own-answer and insufficient-context paths discoverable?
- Do Few-shot Suggestions accelerate work without being mistaken for Evidence, precedent or recommendation?
- Does the visual improve a decision or Work Result, or would plain text have been faster?
- Can the participant tell what their answer changed and what still requires a human Decision or Effect?
- Does the same composition remain usable under Boutique role compression and Growing contribution/handoff?

## 11. Explicit anti-patterns

- dashboard carpet or one visualization per step;
- general graph browser presented as the user's work;
- charting qualitative model confidence as if it were measured business data;
- decorative flowchart that merely repeats navigation;
- closed multiple-choice set for an open consulting judgment;
- default-selected AI recommendation;
- Few-shot example presented as firm proof without verified origin and usage rights;
- user response silently converted into Decision, Approval, publication or other Effect;
- inaccessible visual without equivalent text/table access;
- explanation as a long chat transcript instead of a contextual work object.

The exact block composition, labels, placement, density and animation remain prototype hypotheses. They are ratified only after observed use demonstrates that they improve comprehension, work quality or responsible speed.
